# 设计提案：发布项目资料快照，而非挂载项目目录

**状态：v1 字节格式已有[独立离线校验工具](./README.md#离线校验项目资料快照)，尚未实现查看器。** 校验通过只表示字节和格式匹配，并不授予 Web 权限。运行时变量、挂载与 GET 接口仍是候选契约。

场景：NAS 的部署者想让自己在另一台设备上查阅两份项目说明。为读这两份文件，聊天容器无需访问整个仓库。v1 建议只做**一个实例、一份经部署者核对的快照、其中若干份可点开的纯文本文档**。原文件后来被编辑，网页仍显示已发布的版本，直到下次发布。

## 授权给谁

| 主体 | 可做的事 | 边界 |
| --- | --- | --- |
| 部署者（控制部署配置） | 挑选文件、核对文件名和完整文字、发布、替换或撤销这一批资料。 | 此权力来自部署环境，不来自 Web 登录令牌；没有浏览器或聊天内的授权命令。 |
| 已登录的实例所有者 | 打开资料目录，显式点开其中一份文档。 | 现有服务是单所有者：同一实例的各个有效登录看到同一批文档。不是按设备、角色、会话或账号分别授权。 |
| 模型服务 | 继续接收用户明确发送的会话消息。 | 打开资料不构成发送同意。查看器不绑定聊天、不建附件、不把资料写入提示词、搜索索引、记忆或会话卷。 |

这与[手动附件](./README.md#手动发送文本附件)是两条不同的数据流：附件由浏览器用户点「发送」后进入历史；资料由部署者发布，只到登录用户的预览。用户自己复制一段再作为普通消息发送，是另一项明确操作。

## 发布什么，如何隔离

1. **只收审核后的字节。** 发布者在运行容器、仓库和镜像构建上下文之外准备一个普通 JSON 文件，一次明确选择一个项目的文档。v1 不扫描目录、不展开链接、也没有按路径或 URL 读取的字段。部署者能读到的其他文件（含配置、凭据）不在授权范围；文件名后缀无法代替发布前的内容核对。
2. **格式与限额。** UTF-8 JSON 对象的字段严格为 `version`、`project` 和 `documents`，键顺序任意。v1 使用原始 JSON 整数字面量 `1`（不是字符串、`1.0` 或 `1e0`）；`project` 是 1–80 UTF-8 字节的单行显示名，不能含路径分隔符、控制字符或双向文本控制符。`documents` 为 1–32 项，每项仅 `{name,text}`，沿用[现有文本校验](./text-file.ts)：非隐藏 `.txt` / `.md` 基名至多 128 UTF-8 字节，正文非空且每份至多 32 KiB。所有正文合计至多 256 KiB，整个输入最多 2 MiB（含 JSON 转义）。拒绝额外字段、重复 JSON 键（含转义后的同名键）、规范化后重名的文档（`NFC` 后转小写）、路径型名称、非法 UTF-8 和不成对的代理字符。JSON 文件本身不带 BOM；正文中的合法 BOM、换行和围栏照原文保存，不当作指令。

   ```json
   {"version":1,"project":"发布手册","documents":[{"name":"入门.md","text":"首次使用：先阅读版本说明。\n"}]}
   ```

3. **双重选择，启动时一次读取。** 提议用部署配置 `DEVA_PROJECT_DOCS_SHA256`（64 个小写十六进制字符）固定部署者核对过的**整个导出文件原始字节**，不重新序列化 JSON，预期摘要来自独立的部署配置；另由可选 Compose 配置把**这一份文件**只读挂载到固定的 `/run/deva-project-docs/snapshot.json`，使用长格式 `type: bind`、`read_only: true`、`bind.create_host_path: false`。不挂仓库、导出目录或 Docker socket。未设置变量的基础版不探测这个路径；文件恰好存在也不算授权。
4. **验证后才服务。** 发布文件放在部署者控制的独立目录，避免宿主路径或父目录被其他用户替换；Docker 在宿主解析源路径，容器无法替部署者证明源头。读取端只打开固定挂载点：核实单文件只读挂载、普通单硬链接文件，拒绝链接、目录及特殊文件。先在 Linux 上固定并检查文件对象，再经该对象读取，避免先检查路径、随后按可替换的名字重新打开。实际读取超过上限即拒绝整包，并复核读取前后的文件状态及完整字节摘要；整包验证成功才发布到内存。之后只从内存取值，不按名字拼路径、不保留可重读的文件句柄、不热更新。显式启用但挂载可写、文件缺失、摘要错误或内容无效时，启动失败且不监听；撤去可选配置可恢复基础聊天。默认部署不受坏导出文件影响。

这是数据隔离，不是抵御已被接管的服务进程：查看器与聊天服务若在同一进程，该进程可以接触**已发布资料**。隔离的关键是根本不向它提供原项目、未发布文件或新的执行权限。互不信任的所有者使用不同实例、数据卷、令牌和主机名；同一主机名的不同端口不是 Cookie 隔离边界。

## 候选读取接口与显示

| 请求 | 已启用时的最小响应 |
| --- | --- |
| `GET /api/project-docs` | `{project,generation,documents:[{id,name,bytes}]}`。只列显示名、正文 UTF-8 字节数和标识；不列正文、宿主路径、文件摘要。 |
| `GET /api/project-docs/:generation/:id` | 显式打开后只返回该项 `{generation,id,name,bytes,text}`。不提供整包下载、写入、发布、挂载、热重载或「发送给模型」接口。 |

- `generation` 与 `id` 是进程加载时分配的随机 128 位标识（32 个小写十六进制字符）。同一快照重启也重新发号。ID 不是能力令牌：每次读取复用[现有登录与同源策略](./server.ts)。对规范的读取请求，错误的 Host、不匹配的 Origin 或跨站请求为 `403`；来源校验通过后，无效、过期或旧进程的登录为 `401`。有效登录在关闭状态、未知 ID 或旧代次请求时一律收到通用 `404`，没有指向原文件的回退。显式启用后，已登录且来源正确的 `POST` 对已知只读路由返回 `405`（`Allow: GET`）；不存在 Web 发布或授权路由。保持既有的未知查询串 `404` 和写请求来源校验。
- 关闭时保持现有启动响应与页面不变。启用时，登录后的启动信息最多增加一个可用标记；不携带目录、ID 或正文。用户点「项目资料」才取目录，点文档才取正文。用纯文本显示（包括 Markdown、HTML 和链接），不解析图片、脚本或外部资源；列表、查看与关闭都应是零模型调用、零聊天卷写入。
- JSON 编码后的清单上限 32 KiB、单项响应上限 200 KiB；沿用连接数限制，写入超时或断开即释放响应。响应使用 `Cache-Control: no-store`。不预取正文，不写浏览器存储、地址栏历史、服务日志、遥测或代理缓存；访问日志应隐藏文档 ID。切换文档、离开视图、退出或登录失效时取消在途读并清理视图；晚到响应需核对原登录和代次。页面从历史缓存恢复时先重新确认登录，不能把旧 DOM 当成一次新授权。

## 撤销与重新发布

- **替换**：审核新的导出，原子发布到新文件并配置新的预期摘要；停止旧实例并确认它已退出、旧连接已关闭，再用新文件重建。**撤销**：同样先停止旧实例，从部署配置去掉摘要与挂载，以原聊天数据卷启动基础服务。不要删除聊天卷。切换期间在途回复会受影响，用户需要重新登录。
- 生效点是**旧服务及仍可访问的旧副本已经退出**，不是改了源文件、移动了挂载、清空了网页或单个设备登出。退出只撤销当前登录。新进程拒绝旧 Cookie，新登录也无法用旧代次取文档。已到达浏览器的字节、用户复制的文字和截图无法追回；v1 不承诺即时热撤权或远程擦除。

本地 Linux 合成文件实验验证了撤销边界：原子替换文件名后，重新打开读到新版，先前固定的文件描述符仍读到旧版；随后删除文件名也没有收回这些字节。这是文件语义实测，不代表候选查看器已上线或容器撤销已验收。

## 进入实现前的验收门槛

| 场景 | 必须观察到的结果 | 本次状态 |
| --- | --- | --- |
| 基础实例，无授权 | 默认 Compose 只有聊天数据卷，没有宿主项目挂载。匿名读取候选目录或详情为 `401`；登录后为 `404`。网页尝试发布、或把文档引用塞进发送接口，均不能获得资料或触发模型。 | [默认 Compose 配置门禁](../../test/headless-compose-default.test.mjs)与[真实服务回归](../../test/headless-chat.test.mjs)验证关闭态；这不是成品容器或查看器的正向验收。 |
| 发布两份、另留一份未发布 | 真正的非 root 容器只见指定快照文件，目录只含两条元数据，显式读取一条只返回一条；访问未发布文档为 `404`。 | 待实现与原生容器验证。 |
| 快照字节无效 | 数量及 UTF-8 字节上限与上限加一、重复键/重名、非法编码和原始字节摘要不符均整包拒绝；诊断不带路径或正文。 | [校验器测试](../../test/project-snapshot.test.mjs)和[离线进程测试](../../test/snapshot-check-cli.test.mjs)覆盖；不代表挂载已授权。 |
| 文件授权无效 | 拒绝特殊文件、可写挂载和读取中被替换的文件；没有半份目录或意外创建的挂载源。 | 待实现与原生容器验证。 |
| 浏览、切换和退出 | 用真实浏览器检查含字面 HTML/链接的正文、迟到响应与返回页面；无额外资源请求、模型请求、会话文件变化或浏览器持久化。 | 待实现。附件测试不能替代资料授权测试。 |
| 撤销和换版 | 旧实例确实消失；新实例拒绝原 Cookie，重新登录后旧 ID 为 `404`。撤销后资料入口消失，原有聊天仍可读取并续聊。 | 待在不同容器与同一聊天卷实测。 |

**范围决定：** 在离线字节校验通过的基础上，下一阶段只考虑固定位置、显式授权的只读挂载，再接入手动预览，并保留上述关闭态测试。需要实时仓库目录、逐设备授予或热撤权时，须另行设计。文件写入、终端、浏览器接管和 MCP 不随这份提案获得权限。
