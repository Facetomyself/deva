# Deva 无桌面 Web 工作台（开发版）

在无图形桌面的 Linux 服务器上，从浏览器认领实例、登录，使用**桌面同源的会话布局、编辑器、消息气泡和模型设置**。网页现可用配置好的服务商进行通用文本对话：新建会话、选择模型、看到流式回复、中途停止、刷新续接并读取已保存的历史。模型设置、密钥和自定义头仍由同一已认证实例管理。这不是手机版、中转或完整 Agent 桌面：执行工具和协作任务仍待移植。会话现在可以关联已授权项目，但这种关联不给模型授予目录访问权。人工浏览器接管是一个需要独立沙箱的可选组件，默认关闭；受支持的聊天附件如下。

## 整理对话和选择下次使用的模型

在对话顶部可改名、归档或还原。清空自定义标题会根据首条用户消息重新命名；若首条只有附件，则使用附件名称。归档只改变显示分组，不删除历史，也不把该对话排到最近位置。其他同账号网页会收到一个只提示「列表已改变」的通知，随后重新向服务端读取；标题、内容和附件均不在该通知中广播。

已确认的 Web 对话可单独固定一个已启用的模型，也可选择「跟随默认」。更改偏好本身不会向模型发请求。跟随模式在下一次实际发送时按服务端当前角色模型或全局默认解析；同一个已受理请求重试时仍返回原来的回合。两个页面同时修改会返回版本冲突，保留输入供核对；正在进行的回合不被中途切换模型。旧桌面复杂会话维持原来的只读保护，非默认思考档位仍待单独验收。

### 未读提示与上下文用量

同一工作台所有者在两个浏览器中登录时，共享会话的已读状态。侧栏头像上的红点表示这段对话有尚未确认的新内容。只有当前页面在前台、已选中这段对话、并已显示最新一条消息时，工作台才向服务器确认已读。仅在后台打开页面、查看其他会话或停留在设置面板，都不会替用户清掉红点。新内容先到、旧确认后到时，服务器保留新内容的未读状态。重复确认同一版本不改文件，也不重复通知其他窗口。

点击输入区模型选择器旁的灰色圆环，可查看本对话使用的上下文窗口及读数来源。「上次请求 · 实测输入 token」表示服务商为该会话、该模型、该次请求实际返回的**输入量**，不是累计费用或下一次请求的精确预报。没有可用回执，或切换到其他生效模型时，改用保存历史的字符与媒体估算，并标为估算。模型失效时不沿用旧数字。查看圆环不调用模型，也不触发历史压缩；当前 Web 引擎没有自动压缩阈值。

已读时间保存在数据卷根目录的 `read-state.json`，只存会话 ID 和服务端确认的时间。通过附有当前游标的请求推进水位，重启后仍可读回；失效的登录或上一个进程的游标不能确认新内容。已有文件损坏或写入无法确认时，页面提示重新核对，服务保留已有记录，普通对话仍可使用。备份时与原数据卷一起保存。

**独立验收。** 在已有依赖的仓库中执行 `pnpm --filter @deva/headless build`，然后执行 `node scripts/workbench/container-conversation-status.mjs --fixture-only`。这会在私有临时目录中用两次真实服务进程启动、一次本地合成模型请求，核对用量和已读水位的恢复；这不是 Docker 测试。在专用的非 root Linux/amd64 测试机（Node 22、Docker Engine 28+）上，可用以下命令验收成品镜像，无需改动已有部署：

```sh
docker build --platform linux/amd64 --target runtime -t deva-workbench:conversation-status-verify .
image_id=$(docker image inspect --format '{{.Id}}' deva-workbench:conversation-status-verify)
node scripts/workbench/container-conversation-status.mjs --disposable-image "$image_id"
```

## 在自己的浏览器复制、引用、粘贴和全屏

- 在一条消息的可见正文中选中文字后右键，或在该消息文本获得焦点时按 **Shift+F10**。**复制**只写到当前用户的浏览器剪贴板；只读历史也能复制。**引用**使用与桌面相同的引用条，只出现在可写的普通会话中，引用与已有正文、附件分开保留，点击 × 只移除引用。每个会话的未发送草稿独立，刷新或重新登录不保留这些草稿。
- 在输入框使用系统粘贴手势（Windows/Linux：**Ctrl+V**，macOS：**⌘V**）。工作台只从这一次原生粘贴事件取纯文本；富文本中的 HTML 和 URL 列表不会作为命令、链接操作或文件路径执行。一次可粘贴 256 KiB，实际发送仍按整条消息（含引用）的 12 KiB 上限校验。文件粘贴仍走原有的会话附件入口。粘贴和引用本身不会创建模型请求；点击发送或按原有发送键才提交。
- 在对话页面，**Ctrl+B**（macOS：**⌘B**）切换对话侧栏；编辑器、输入法组字、弹窗、菜单和其他业务页保留自己的按键。左侧导航的全屏按钮只控制当前页面；浏览器退出全屏时图标同步。它不是窗口最大化、操作系统 F11 状态或对服务器内置浏览器的遥控。安全上下文、权限策略或浏览器不支持时，界面展示相应状态。
- 在设置底部可见服务端平台。Linux 容器仍显示 Linux，即使操作电脑是 macOS；快捷键则以当前浏览器的客户端语义为准。服务端没有用于读取剪贴板、采集选区或控制用户浏览器窗口的 RPC。兼容浏览器上，文档的 `Permissions-Policy` 禁用异步读剪贴板，只为同源页面保留写入和全屏权限。

## 个人资料、角色与记忆

- 左侧头像打开桌面同源的个人资料与头像编辑器。生成头像样式与上传的静态图片独立保存；图片上传、清除和角色编辑带修订号。页面检测到另一标签页已写入时，应先重读再编辑。
- 花名册可以创建普通角色、编辑提示和模型偏好、调整顺序、启停和管理头像。点击已启用角色可开始文本对话。服务器从角色库读取身份而非照收浏览器传入的指令；同一会话保持原角色绑定。默认通用角色受删除保护，有会话、任务、扩展等实际引用的角色会提示冲突，而不是静默改绑。
- 全局、角色和项目记忆分别管理。可以手动新增、查看、编辑、删除或确认清空选中范围。项目只以管理员登记的目录 ID 选择；在此阶段选择项目不授予聊天读取目录文件或执行命令的权限。旧记忆的首次实际修改会在数据卷内留下迁移备份。
- 默认无授权项目。若要使用项目范围，在服务器上准备一个**专用**项目父目录，只放准备开放的项目子目录。设置 `DEVA_WORKSPACE_PARENT` 为其绝对路径，并将 `-f compose.workspaces.yaml` 追加到下面采用的 Compose 命令；该可选文件把目录只读挂载到 `/workspaces`。机器上的其他目录、个人家目录和 Docker socket 均不应挂入。

## 管理已保存的技能

打开 **设置 → 扩展**。列表来自当前实例的数据卷，使用桌面的扩展行和详情组件。三个应用内置项只显示目录信息与固定状态；选择自定义技能才打开它的 `SKILL.md` 详情。页面展示来源、说明、角色范围和纯文本正文；详情接口返回的建议工具等字段是文档资料，并非运行许可。文件里的图片、链接、脚本和其他资源都不会被自动打开。

开关保存的是桌面格式的启用偏好。在技能详情中打开 **可用角色**，可选择「全部角色」「不指定任何角色」或勾选具体角色，确认后保存。全部和零个是两种不同状态：前者删除此项在角色映射中的覆盖，后者保存空数组。已删除的旧角色引用保留原值，只有人工修改才会改变。另一个登录或宿主先改了文件时，页面会提示核对新版本，旧操作不会自动重放。只在面板打开时检查目录变化。

**这些设置不启动技能。** Web 对话不会因为某项记录为启用就加载其正文或开放额外工具。此页没有安装、导入、删除、执行脚本、MCP 连接或修改技能正文的操作；已有普通技能记录可与停写后的桌面数据副本一同迁移。

- 默认 Compose 容器内原生位置为 `/data/skills/<id>/SKILL.md`，偏好位于 `/data/config.json` 下的 `skills.enabled` 与 `skills.roles`。列表不会创建缺失的技能目录。配置有修订号和单写者保护，写后需读回；源 Markdown、旁边的资源和配置文件中的其他字段保持原样。
- 支持当前应用用户拥有的、与数据目录在同一文件系统挂载中的普通单链接文档，最多 128 个自定义技能、每份文档 128 KiB、文件首部元数据 16 KiB、目录中文档合计 4 MiB。扫描最多检查 512 个直接条目。链接、同名冲突、超限和未支持的结构会显示错误，而非显示成空列表。常见凭据字段或明显的私钥内容会被拦截；这项检查并非通用敏感信息识别器。
- 适用于专属数据卷，配置作为普通文件通过临时文件替换写入，保留安全的原 UID/GID 和传统 Unix 权限。依赖自定义扩展 ACL、xattr 或多写者语义的原件应保留独立备份。配置只读时仍可查看合格记录。

## 把附件发给对话模型

选择、粘贴或拖入文件时，浏览器先把字节暂存在**当前会话**中。输入区显示可预览或撤回的附件卡；只有点击发送，才会将选定文件纳入模型请求。文件名是显示标签，不是客户端或服务器路径。不要把“在项目里浏览文件”与“将文件发给模型”混为一谈。

| Web 支持格式 | 限制 |
|---|---|
| 常见 UTF-8 纯文本、Markdown、代码或配置文件 | 单文件 512 KiB；独立 HTML、SVG、二进制和未知格式不作为网页内容上传。 |
| 静态 PNG、JPEG、WebP | 单图 2 MiB，边长不超过 4096；按会话鉴权提供缩略显示和原图查看。当前使用同一经过校验的原图字节，尚无单独的小尺寸网络资源。 |
| PDF | 单份 20 MiB；以文档内容块走 Anthropic 或 OpenAI Responses。Chat Completions 没有原生 PDF 通道，发送前明确报错；工作台不在同源页面内执行或预览 PDF。 |

每条消息最多 4 个附件、合计 20 MiB；同一会话已提交的附件累计上限为 48 MiB。草稿默认保留 24 小时，每个会话最多 32 份或 40 MiB，实例总量最多 512 份或 256 MiB。成功确认会话内容后释放对应草稿额度；中途关闭页面可能留下未发送的草稿，期限过后在清扫时回收。已发送图片可在刷新或容器重建后按当前会话查看；重试同一个已确认的发送请求不会重新向模型计费。工具卡、交付件、任意桌面文件和文件夹路径的自动处理不属于这条流程。

## 下载交付物，或把回复保存为文件

在已结束并确认写入磁盘的助手回复旁，点击 **导出 Markdown** 或 **导出纯文本**。交付卡使用桌面原有的文件行和折叠布局。点击卡片上的下载按钮，原始 UTF-8 字节才会写到当前浏览器的下载位置。重复导出同一轮、同一格式会返回原来的交付记录，不会再次调用模型。导出的是可见的最终回复，不包含推理、工具参数或模型配置；这并不表示在服务器上运行了文件生成工具。

旧桌面对话的交付记录仍为只读。服务只认可桌面 `present_files` 的成功调用、配对的结果和已经保存的交付清单；不会从随意一段聊天文字中猜测路径。只有落在管理员已挂载项目内的合格文件才会显示。原生路径须在本实例的授权目录中仍然有效；原机器路径、链接和隐藏项目不会被映射成浏览器文件。可以下载受支持的数据文本和静态图片（单份 2 MiB）、PDF 和可识别的无宏 `.docx`、`.xlsx`、`.pptx`（单份 8 MiB）。Office 识别核对包结构、主要 XML 与内部关系；含未受支持的部件（如嵌入二进制、打印机配置）、外部关系、旧版二进制格式或加密内容时，卡片会标明该类型暂未支持。Office 和 PDF 均作为附件交给浏览器下载，不在同源页面执行或预览。只有校验后的 PNG/JPEG/WebP 可在网页内预览。对可定位的桌面交付项，点击「在工作区文件中定位」会选中同一项目和相对路径，不会启动服务器的系统文件管理器。

下载、预览和定位都检查当前登录、对话、交付组、原始序号和文件版本。已移动、已更换、过大或未支持的文件都有独立状态；变更后需要先刷新交付卡。这些地址不是公开分享链接。备份要包含数据卷：已导出回复的确认记录和原会话共同决定可下载的字节；项目中的桌面交付文件则需随自己的项目另行保管。

## 把项目关联到一段对话

1. 从对话的项目选择框选择管理员已挂载的项目，点击 **关联到此对话**。只在文件面板里浏览目录，不会改变这段对话的项目。其他会话保持各自的选择。
2. 对话标题旁会显示已保存的项目。点击标签打开该项目的文件；点击 **打开项目记忆** 才读取这一个项目的笔记。绑定本身不读取或上传文件、笔记和 Git 历史，也不向模型发起请求。
3. 已配置默认项目的角色在**新建**对话时继承该项目。后来修改角色默认值不会改变原会话。可以手动更换项目，或点击 **解除关联**。

绑定通过不透明项目 ID 和会话修订号保存。若另一个窗口先保存，当前窗口保留选择并提示重新核对。挂载被撤回或目录被同名替换时，旧会话将项目显示为失效；服务不会把替换后的目录识别为原项目。即使容器重建时没有工作区挂载，所有者仍可解除旧关联。只有路径、缺少已验证项目标识的旧角色资料可在管理页重新确认；不会仅凭旧路径自动挂载给新会话。

## 手动打开服务器项目的文件

配置专用项目父目录后，工作台的文件夹按钮会显示已授权的项目。打开目录只读一层；打开文件只读取该项目的相对路径。在文件面板内切换项目仍是临时浏览，只有显式保存会话关联才会持久化；文件内容不自动发送给模型。文本预览上限 2 MiB；二进制和过大文件只显示类型/体积提示。隐藏文件、符号链接、硬链接、设备和项目内额外挂载不在此授权范围。

默认用 `compose.workspaces.yaml` 只读浏览。要允许所有者在网页里保存**已有文本文件**，改用 `compose.workspace-edit.yaml`（两个工作区 override 只选其一）。它把同一专用文件夹挂载为可写，并显式开启 `DEVA_WORKSPACE_WRITE=1`；宿主的属主、Unix 文件和目录权限仍须允许容器 UID 1000 写入。默认不提供新建文件、删除、执行、Git 操作或任意宿主路径访问。服务检查挂载与文件身份、以同目录临时文件替换；保存保持普通 Unix 模式和所有权，不复制扩展 ACL/xattrs，不要对依赖这些属性的文件开启编辑。

保存使用服务器读回的版本。另一个标签页或宿主上的编辑改了文件，会收到冲突；网页保留草稿，显式重新读取后对照磁盘版本，再由用户决定是否保存。不会自动重放陈旧内容。此机制保证本服务处理的同版本竞争只会有一个成功；它不是针对其他未协作文件写入者的操作系统级写锁。此阶段的冲突预览也不等于 Agent 检查点/历史回退。

### 在目录树中定位，以及单独启用新建文档

打开文件后点击 **定位所在文件夹**，工作台会重新核对项目、逐层展开目录、把键盘焦点移到实际的文件夹行；已打开的文件和编辑草稿保持原状。从对话标题的已关联项目入口同样可定位项目根目录。此操作在只读挂载下就能使用，也不会在服务器上启动文件管理器。

浏览、编辑已有文件、创建新文档是不同的部署权限。现有只读和仅编辑的部署维持原样。要新增**人工创建**权限，在编辑配置之后追加第三份文件：

```sh
export DEVA_WORKSPACE_PARENT=/absolute/path/to/approved-projects
docker compose -f compose.yaml -f compose.workspace-edit.yaml -f compose.workspace-create.yaml up -d --build
```

1. 在 **工作区文件** 中打开所需项目与现有文件夹，点 **新建文档**，选择文件夹、输入 `.md` 或 `.txt` 文件名和正文；空文档也可创建。此时是当前页面的草稿，没有写盘。
2. 点 **核对目标**。服务检查实际目录权限及该名字仍为空，并将核对记录绑定到当前登录、项目和目录。记录有效期 2 分钟。再点 **创建文档** 才会发布；新文件是当前服务 UID 拥有的普通文件，权限 `0600`。如果另一窗口先创建同名文件，原文件保持原样，失败窗口保留草稿。
3. 如果创建响应中途断开，点 **核实创建结果**。页面只检查原记录并重新读取目录与文件版本；不会再次创建。关闭表单或取消仅释放核对记录，不删除已写入的文件。容器重建后仍可从项目中重新打开已落盘的文件；旧核对记录和登录身份失效。

文件名最多 200 个 UTF-8 字节，正文最多 2 MiB。只在已授权的现有目录中创建文档；隐藏或含路径分隔符的名字、控制文件、明显凭据内容和执行脚本不在范围内。服务用同目录临时文件、同步写盘及不覆盖目标的硬链接发布，随后从原生文件读回。底层文件系统须支持这些操作；若发布后仍无法确认，保留磁盘现状并报告未确认，不回滚他人文件。不会创建目录、删除文件或把工作区文档交给对话模型。

**独立验证这三种部署权限。** 以下是验收命令，不是启动常驻服务的命令。在专用的原生 Linux/amd64 测试机上，以有本地 Docker 操作权限的普通用户执行；需要 Node 22+、Python 3、Docker Engine 28+、Compose v2，以及 `/tmp` 支持普通用户设置 POSIX ACL。

```sh
docker build --platform linux/amd64 --target runtime -t deva-workbench:project-documents-verify .
image_id=$(docker image inspect --format '{{.Id}}' deva-workbench:project-documents-verify)
node scripts/workbench/container-project-documents.mjs --disposable-image "$image_id"
```

命令先核对镜像 ID，再使用临时项目和回环端口实测默认、仅编辑、允许新建三种配置，并重建工作台检查数据。测试不使用已有工作区、数据卷和密钥，也不需要 `sudo`。只想在本机检查测试目录与 ACL 能否建立时，可用 `node scripts/workbench/container-project-documents.mjs --fixture-only`；该命令没有运行 Docker，结果不计入容器部署验收。

### 在真实 PTY 中查看已保存的文本

需要终端式分页时，可给已授权的工作区增加[只读 TTY 查看器](../terminal-worker/README.md)。在 `compose.yaml` 与 `compose.workspaces.yaml` 之后再加入 `-f compose.terminal.yaml`，然后从已打开的文件选择 **打开 TTY 查看器**。只有这一点击才会把经版本核对的文本快照送入隔离工作器。在窗口内可以翻页、调整行列和退出；它不会启动宿主 shell 或把输入发送给模型。工作器离线只影响这个可选入口。

## 手动查看项目的 Git 资料（只读）

浏览文件与授权 Git 历史是两份不同的许可。先准备只读项目父目录，再用 `DEVA_GIT_PROJECTS` 指定允许查看 Git 的**直接子目录名**；项目中可能有历史版本的源代码，须按实际希望公开给当前所有者的范围选择。没有配置时，网页维持原工作区界面。

```sh
export DEVA_WORKSPACE_PARENT=/absolute/path/to/approved-projects
export DEVA_GIT_PROJECTS='["Documentation"]'
docker compose -f compose.yaml -f compose.workspaces.yaml -f compose.git-inspect.yaml up -d --build
```

打开工作区并选中该项目，然后点击 **Git 查看**。只读面板与桌面复用分支按钮；只有明确点击才读取状态、分支、历史或文件差异。存盘为普通 SHA‑1 loose objects 或常见 pack/idx v2 的仓库均可查看，无需在产品容器安装系统 Git。Git 元数据和 diff 不发给模型；没有后台 Git 轮询，不执行仓库配置、钩子或文本转换器。

- **变更**比较可见的已跟踪普通文件。暂存视图比较 HEAD 与索引，工作树视图比较索引与磁盘。文件被更改、视图过期或其他登录重用引用时，需要重新选择；切项目后不继续显示原项目的数据。
- **历史**最多看 100 个首父提交；远程跟踪分支仅反映本地缓存。没有读取或连接远程，上游关系及领先/落后数量未知。未跟踪文件、重命名推断、`.gitattributes` 转换和子模块内部状态不在本视图内。
- **范围**限制为普通仓库根下的真实 `.git` 目录，已登记项目被替换后需要重新检查部署授权。外置 gitdir、linked worktree、alternate 对象库、SHA‑256、部分或超限仓库会给出相应状态。每次读取受时间和字节上限约束；缺对象或预算耗尽不等于仓库干净。此面板不提供暂存、丢弃、提交、切分支、fetch/pull/push 或凭据设置。

## 查看桌面定时任务和预览时间

点击左侧导航栏的闹钟图标 **定时任务**，即可读取当前数据卷里的桌面任务。任务列表会取代会话侧栏：宽屏下与详情并排，窄屏下位于详情上方；点回对话可回到原来的会话。列表只显示概要；选择任务后才显示指令正文、角色和模型引用、关联会话标识及已记录的运行历史。正文按纯文本显示。任务文件缺失时为空列表；文件损坏、布局不受支持或超过读取上限时会显示错误，不会生成一份空文件覆盖原件。

**此页面不启动调度器。**「上次运行」和「下次运行」来自原桌面记录，不代表容器已经执行、正在排队或会自动触发。可以用桌面同源的日程编辑器选择一次性时间或五段 cron，明确给出 IANA 时区（如 `Asia/Shanghai`），点击 **预览** 查看对应的本地时间和时区。预览不写任务、创建会话或连接模型。跨夏令时切换时，以预览给出的实际时刻为准：重复或缺失的墙钟分钟依桌面日程算法解析。

当前唯一的任务写操作是**暂停一条现有的活动任务**。确认后，服务仅更改该条的 `status` 和 `updatedAt`，保留历史、原始 `nextRunAt` 及其他任务字段。工作台持有数据卷写锁，条件写入和磁盘读回都成功后才显示已暂停。两个页面并发操作时，另一页面须刷新、核对版本。旧任务文件可读不代表可写；写入要求真实的应用所有者私有目录（0700）及普通任务文件（0600）。新建、恢复、立即执行和系统通知仍是单独的功能，此页面没有这些动作。

## Docker Compose（linux/amd64）

在本分支的仓库根目录执行：

```sh
docker compose up -d --build
docker compose ps
docker compose exec workbench node /opt/deva/apps/headless/src/cli.mjs claim
```

最后一条需要交互终端，只在调用者的终端显示 10 分钟有效的一次性链接。用浏览器打开，在页面为实例设置至少 12 个字符的口令。其后直接访问 `http://127.0.0.1:18787/` 登录。普通远端 SSH 部署可先将服务器 `127.0.0.1:18787` 转发到自己机器的同一回环端口；Compose 始终只发布宿主回环端口。服务器只有独立 Compose v2 时，命令前缀用 `docker-compose`。缺少 Buildx 的旧 Docker 可先以 `docker build -t deva-workbench:dev .` 原生构建，再 `docker-compose up -d --no-build`；无需改变 Docker 守护进程设置。

- HTTPS 反代：设置 `DEVA_PUBLIC_URL=https://你的域名` 并重建容器。反代须保留公共 `Host`，应用忽略 `X-Forwarded-Host`；认证 Cookie 在 HTTPS 下为 `Secure`、`HttpOnly`、`SameSite=Strict`。变更宿主回环端口可用 `DEVA_PUBLISHED_PORT`。
- 通常可在桌面设置页直接添加公网 HTTPS 模型。要连接内网、回环或明文 HTTP 模型，部署者须在 `DEVA_PROVIDER_ORIGINS` 明确列出允许的**精确 origin**，多个以逗号分隔。容器中的 `localhost` 只代表本容器；本机服务应通过设计好的私有网络连接，而非向公网发布。服务按持久化配置匹配地址和凭据，固定解析结果，不带工作台 Cookie，不随重定向发送鉴权头。
- 模型自定义请求头的值与 API key 存入加密密库。设置回读只显示保存状态/占位值；修改端点后要为新端点重新录入凭据。并发编辑发生冲突时刷新设置，而不是覆盖另一标签页的配置。在设置页启用所需模型后，回到会话输入区选择该模型。[文本回合限制、恢复和幂等语义](src/chat/README.md)。
- `GET /livez` 检查进程；`/readyz` 和 `/healthz` 检查已实现服务和构建产物是否就绪，不证明模型在线或所有桌面能力已经移植。
- `data` 卷保存配置、账号验证信息和密文，`keys` 卷保存独立主密钥。停服务后一并备份，妥善分开保管；回滚镜像不应删除卷。启动时已有密库缺主密钥、密钥错误或数据损坏会报错，不会重置账户。不要让桌面和服务器同时写同一数据目录；迁移桌面配置先制备独立副本，默认不会静默改写桌面明文自定义头或解密桌面系统密钥。普通 `docker compose down` 保留这两个卷。

### 把备份恢复到新的实例卷

1. 停止工作台写入。独立保存 `data` 和 `keys` 两个卷，并保留文件的 UID、GID、模式和原始字节；仅保留加密的数据卷不足以恢复模型凭据。运行时 Unix socket 和临时浏览器 profile 不是备份内容。
2. 新建一对空卷做试恢复，把数据和它的**同一把**主密钥分别还原到自己的卷；使用相同镜像启动隔离实例。不要覆盖仍在服务的卷，也不要为已有密文初始化新密钥。
3. 使用原账号重新登录。旧浏览器 Cookie 应失效；核对会话、归档次序、模型偏好及历史附件。用已配置的测试模型做一轮新的请求，证明恢复的密钥能解密实际凭据。若再提交一个**旧**请求 ID，应读到原回执而不是另发模型请求。

已在原生 amd64 上用合成数据演练这条流程：停写后分别复制数据卷和密钥卷，再恢复到全新的卷；对比字节、重新登录、读回历史和新模型调用均通过。这验证了同版本恢复，不代表任意未来版本可直接降级。

### 已有内建 bridge、缺少端口发布 NAT 的主机

默认 Compose 会新建项目网络并发布一个回环端口。如果主机现有 Docker `bridge` 可以使用，但新建 bridge/端口发布失败，可显式采用私有 bridge 模式。它不修改防火墙，不创建新的 Docker bridge，**宿主不发布应用端口**。仅在信任该内建 bridge 上其他工作负载时使用；工作台认证仍开启。

```sh
docker build -t deva-workbench:dev .
docker compose -f compose.yaml -f compose.private-bridge.yaml up -d --no-build
docker compose -f compose.yaml -f compose.private-bridge.yaml exec workbench node /opt/deva/apps/headless/src/cli.mjs claim
cid=$(docker compose -f compose.yaml -f compose.private-bridge.yaml ps -q workbench)
docker inspect -f '{{(index .NetworkSettings.Networks "bridge").IPAddress}}' "$cid"
```

从管理员电脑将本地回环 `18787` 转发到上一步得到的容器地址：`ssh -N -L 127.0.0.1:18787:<容器IP>:8787 <服务器SSH地址>`，然后访问认领链接。容器重建后重新读取 IP。Unix 控制通道始终留在容器内。

## 源码验证

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm workbench:build
pnpm workbench:check
pnpm headless:test
```

`node scripts/workbench/e2e-browser.mjs` 用真实、非 root 的沙箱 Chrome 与匹配的 ChromeDriver 检查认领、模型设置、拉取/添加、两轮真实协议请求、流中刷新续接、停止后的历史以及登出。它只连接本地测试工作台与测试模型；浏览器或沙箱不可用时测试失败，不计作通过。应用的服务端内置浏览器 worker 是另一个能力，与用户浏览器打开 Web 页面是两件事。

独立管理面验收使用 `node scripts/workbench/e2e-library.mjs`，无需模型服务凭据；它使用临时数据卷和合成头像，通过真实浏览器检验资料、记忆、花名册和角色绑定。

裸机需要 Node 22、Linux `/usr/bin/flock`、`/proc/self/fd` 和支持文件锁/目录 fsync 的本地文件系统。`node apps/headless/src/cli.mjs --help` 可查看 `init-key`、`serve`、`claim`、`status` 等参数。一次性凭据与登录口令不要写入源码、镜像或日志。完整功能进度见[能力清单](../../docs/development/web-workbench/parity-manifest.json)。
