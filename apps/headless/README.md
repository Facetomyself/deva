# Deva headless host

无 GUI 工作台的服务器组件。目标是由完整桌面 React 工作台调用同一套业务逻辑；这不是手机版的 relay。当前分支正在把业务从 Electron 中拆出。**仅构建静态工作台或通过以下测试，并不会得到一台已经能够对话的服务器。**

## 已有基础

- 仅部署端的私有 Unix 控制通道可签发短时认领凭据。管理员在网页认领实例后用自己的口令登录；重启保留经 scrypt 派生的验证信息，临时认领、浏览器会话和 CSRF 值不会跨服务重启。和手机设备凭据隔离。
- 同源 HTTP 路由同时校验配置好的 Host、Origin 和写操作的 CSRF。`GET /api/v1/bootstrap` 只给有效工作台会话返回首帧需要的外观配置投影。HttpOnly 会话值不出现在 JSON 中。
- 容器密库采用独立 32 字节主密钥及认证加密，与 Electron 的 `secrets.json` 分开。备份和恢复要同时保管密文和独立密钥；已存在的数据不会在解密失败时默默重置。
- 单写者锁是本地 Linux 文件系统上的 `flock` ，不是 PID 文件或容器私有网络命名空间内的进程锁。主进程或容器退出后内核释放锁。进程应在打开配置和密库之前取锁，并在 HTTP、控制通道与业务收尾后释放。

## 验证

```sh
pnpm install --frozen-lockfile
pnpm headless:test
```

目标环境为 Linux、Node 22 及以上、`/usr/bin/flock`、可用的 `/proc/self/fd` 和支持文件锁及原子文件操作的本地文件系统。使用私有数据目录和独立的主密钥路径；工作区及 PTY 执行进程均不得挂载密库和解密材料。测试使用临时目录、短生命周期回环服务器或 Unix socket，不需要真实账号、第三方模型或可联网的浏览器。
