# Chat event bridge

`installDesktopEventBridge({ onChatEvent, onSessionsChanged }, limits?)` takes the real desktop `chat-bus` registrations and returns `{ journal, uninstall }`. `uninstall()` removes both callbacks, clears history, and ends subscriptions. A new installation creates a new epoch. No module registers a route or starts the bridge at import time.

- `SESSIONS_SCOPE` (`sessions`) emits `{ cursor, type: 'sessions_changed' }`: a signal to re-read the authorized list, never the list contents or the changed session's ID. In addition to `onSessionsChanged`, it invalidates on `turn_start`, `done`, and `member_report`, matching the desktop list refreshes. For an initial output scope, call `chatScope(sessionId)` (`chat:<id>`). It emits `{ cursor, type: 'chat', sessionId, turnId, event }`, with assistant text deltas and selected lifecycle signals. Raw provider errors, thinking, tools, user prompts, and attachments are excluded. These APIs take business events, not arbitrary topics or data; the text delta must be display prose from a trusted producer, never a credential, terminal/screen stream, or a raw upstream payload.
- `journal.snapshot(scope, readState)` returns `{ cursor, state }`. The reader is synchronous and returns a detached, authorized state projection coherent with publications in that scope at the read point. It must include any in-flight data it claims to represent; a read of persisted history alone may lag the desktop stream. Omit the reader only for a cursor-only starting point (`state: null`), not as a replacement for resync state. The journal never retains snapshot state. Async readers are rejected and synchronous same-scope reentry fails with `SNAPSHOT_CHANGED`.
- `journal.subscribe(scope, cursor, { onEvent, onClose? })` registers synchronously. After returning `{ status: 'subscribed', close }`, delivery begins on a later Node turn, replaying everything strictly after `cursor` before live events. The same-tick `snapshotAndSubscribe(scope, readState, callbacks)` returns `{ snapshot, subscription }`. The cursor is `{ epoch, scope, generation, seq }`; `seq` increases per scope generation. The client resumes from its last **applied** cursor, never an advertised or merely queued one. Invalid, foreign, future, or expired cursors return `status: 'fresh_snapshot'` with a reason; none open a subscription. `busy` means the subscriber limit is full; `closed` means the journal has ended.
- `onEvent(frame)` may return `false` to close immediately on backpressure, or a Promise that resolves once the sink is ready for another frame. There is at most one delivery in flight per subscriber and no private replay queue. A sink overtaken by retention closes with `history_lost`; other automatic close reasons include `scope_evicted`, `journal_closed`, `backpressure`, `delivery_timeout`, and `consumer_error`. Explicit `close()` is silent and idempotent. `onClose(reason)` runs off the publisher stack, and callback throws/rejections are isolated. A synchronous CPU-bound callback still blocks the Node event loop and must be avoided.
- Limits: 128 chat scopes (LRU; the list scope is always resident), 256 retained frames per scope, 2 MiB of encoded frames across scopes, 64 KiB per frame, 64 subscribers, and 15 s per pending asynchronous delivery by default. History eviction is oldest-first; a single frame beyond its limit makes a replay barrier rather than creating a silent gap. `journal.stats()` reports usage. `journal.close()` ends the instance.

## Future `/api/v1/events` binding

Keep the route same-origin and authorize an explicit business scope before reading its snapshot or accepting its cursor. A cursor identifies progress, not authority. The list scope covers instance-wide invalidation timing; a future multi-tenant host needs separately scoped invalidations where that timing is sensitive. The full duplex transport should use WebSocket: enforce matching `Host` and an explicit same-origin `Origin` on upgrade (`httpPolicy.check(req, true)`), authenticate the session cookie, and authorize the session/list and each typed inbound command. Keep bounded frame size, subscriber limits, an outbound buffered-byte high-water mark, and ping/pong plus cleanup. For a mutation protocol over WS, define CSRF binding before accepting mutating frames; HTTP POSTs use the existing CSRF header check. Authenticate before snapshots and writes, enforce expiry, and close on logout/revocation (add a revocation hook or recheck the session at delivery and heartbeat; checking only when opening the connection is insufficient).

SSE GET would serve initial chat output only: apply `httpPolicy.check(req)` to Origin/Host, authenticate its cookie and authorize its exact scope, use keepalives and close/abort cleanup, and handle backpressure via bounded writes/drain. End on logout/revocation or expiry just as with WebSocket. A stale cursor must trigger a fresh authorized snapshot, not a partial replay. Neither SSE nor a WebSocket server is installed here; the journal uses only Node built-ins.
