# Web 工作台：桌面渲染器，独立宿主

目标是用无图形桌面的 Linux 服务器运行 Deva，浏览器内完成桌面端业务；现有手机版仍是可选的远程客户端。两种网页的用户权限、协议和构建目标各自独立。此目录记录功能进展；构建通过不等于服务已可部署。

## 目前的切分线

- 桌面继续用 Electron 注册的 `window.deva`。新的生产构建 `pnpm workbench:build` 从同一份桌面 React 工作台和浏览器外框生成两个惰性分块及 CSS，不依赖手机页面或内置 relay。
- 产物是 `apps/desktop/out/workbench/workbench.js`，导出 `mountWorkbench(host, view?)`。这是**供后续 Web 服务加载的 ES 模块，不是单独运行的 Web 服务器**。独立的首用 HTML 入口由 [headless 服务](../../../apps/headless/README.md) 托管：只有网页认领、登录和模型设置已接通，可在同源请求下使用原 ModelSettings。完整工作台仍需实际业务能力才能挂载。
- Web 宿主必须先完成登录、取得首帧设置快照，并提供完整类型的本地浏览器适配器，才可渲染。解析成数据的服务端响应不会成为 JavaScript 代码，也不接受凭 URL 指定宿主模块。
- `view` 默认 `workbench`，`browser` 为内置浏览器的 React 外框。外框不是被浏览网页的内容，也不提供实际浏览器引擎。一个文档只绑定一个宿主及视图；更换身份或退出须销毁该页面。

## 计划中的服务边界

1. 网页认领/登录与完整工作台授权独立于手机的短时配对协议。会话校验、变更权限、资源所有权和 Origin 校验在服务器上进行；不要把 IPC 白名单逐字暴露为万能网络调用接口。
2. 会话总线通过带序号的订阅流同步，命令带请求标识；重连用快照/游标解决初始化与实时事件交错。取消订阅、停止生成、问答审批和检查点恢复都需要桌面/Web 双向契约测试。
3. 配置、模型与会话属于后台实例。服务器密库与解密材料和 Agent/PTY 运行身份隔离；将 `DEVA_HOME` 设为 `/data` 只解决路径，不能代替访问控制。
4. 来访者本机文件按**字节上传**，服务器目录由显式挂载的工作区供选择。交付件用授权的资源 ID 下载，`file:` 不是网络接口。Git 与 PTY 在受限的工作区执行环境中运行。
5. 内置浏览器用启用沙箱、独立运行的 headless Chromium。实时预览仅呈现；人工接管是按标签独占、可撤销的另一项权限。接管与交还保留同一页面状态。

## 分别证明什么

`pnpm typecheck` 检查代码边界，`pnpm workbench:check` 核验接口清单及单元约束，`pnpm workbench:build` 核验浏览器产物和依赖关系；均不能代替带真实后端的浏览器端到端测试。完整验收需覆盖空卷首次配置、模型首轮回复、刷新续聊、断线审批、Git/文件、任务、人工浏览器接管、凭据与备份还原，并在原生 linux/amd64 设备上验证。宿主私有路径、凭据与部署地址不进入公共仓库。
